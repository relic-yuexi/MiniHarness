# 模块二：Memory

调研日期：2026-09-12。本项目基础版落实 session 内历史、摘要和 todo；跨 session 长期 memory 以下作为设计扩展，不伪称已实现。

## 1. 半个月后问曾经问过的问题，怎样召回合理？

面试回答：先判断用户要“上次的答案”，还是“现在该怎么做”。前者找历史事实和当时依据，后者把旧信息作为线索，涉及日期、版本、价格等变化时重新查证，不能把旧答案直接当最新事实。

检索流程设计如下：

1. 用户输入真正 accepted 后、创建本次模型请求前，结合当前问题和最近少量完整消息解析实体、时间、指代。对“上次那个方案”使用近期主题扩展查询；明确 ID、文件名优先精确检索。
2. 先按 user、授权 scope、session/project 和删除标记过滤，再进行关键词与向量混合召回。权限必须在检索层生效，不能先把所有人的内容放进模型再让它过滤。
3. 排序考虑相关性、可信来源、时间和用户明确纠正，选少量互补片段。返回原始证据摘录及 `memory_id/source_event_id/valid_time/recorded_at`，不能只给脱离来源的总结。
4. 最新明确纠正可取代冲突的旧偏好；若只是另一个项目的局部约束，则保留作用域。冲突无法确定时呈现分歧并澄清，不能仅用“时间最新”解决所有冲突。
5. 注入有 token 上限的 memory 数据块，标为检索到的历史信息，附来源与时效，不能变成 system 指令。后续缺事实时允许模型主动检索；不要每个 Step 重复插入同一批结果。

为兼顾 cache，稳定 system/tools 不变；本轮召回内容在当前历史尾部追加并持久化为独立上下文事件，然后追加/关联本轮输入。上一轮已发出的 memory 块原样保留，直到 compact。删除请求属于显式隐私操作，需要删除底层记录/索引和失效上下文，不能用“cache 优先”拒绝用户删除；基础版不承诺跨 session 记忆删除功能已存在。

写入时不把每句聊天都抽成永久事实。原始事件保留可审计证据；抽取长期稳定偏好、明确任务约束、已验证的重要结果，记录来源和范围。摘要中的模型猜测不能晋升为用户事实。更新以新版本和 `supersedes` 关系表达；抽取失败不阻塞当前回答，可以重试，幂等键防重复。

场景示例：用户两周前在项目 A 选 Python 3.11，今天在项目 B 明确要求 Python 3.12。问“上次 A 用什么版本”应回答 3.11；问“这里用哪个版本”应依据 B 的 3.12。两窗口 session 默认互不召回；开启 user 级记忆必须成为明确的产品配置，不能由同一 user ID 自动推导全部共享。

测试关注：同义改写、精确实体、时间问答、跨 session 权限、偏好纠正、局部例外、删除后的不可召回、无证据拒绝臆测、检索内容含注入指令、索引落后与重复写入。指标包括召回正确率、错误记忆引入率、任务成功率、检索延迟及成本，不只看向量相似度。

## 2. 经典框架、趋势与代表性实践是什么？

“存储与召回是核心”这个判断成立，但将 Agent memory 完全等同于 RAG 会漏掉写入策略、事实更新、遗忘、工作状态和程序性知识。RAG 常指检索后增强生成的读路径；memory 还需管理什么值得存、何时失效以及如何维持状态一致。

| 记忆层 | 典型内容 | 本项目位置 |
| --- | --- | --- |
| 工作记忆 | 当前输入、近期消息、pending actions | 内存 SessionState 和 ContextView |
| 情节记忆 | 某时某人说了什么、某工具做过什么 | 不可变 session.jsonl |
| 语义记忆 | 稳定偏好、实体事实、长期约束 | 扩展的带来源事实存储 |
| 程序性记忆 | 可复用方法、操作规则、技能 | 版本化规则/技能，不能把任意旧工具输出提升为规则 |

经典代表包括：MemGPT 用层级存储和受控数据移动管理有限上下文；Generative Agents 将经历记录、反思和规划连接起来；Mem0 聚焦从对话抽取、整合和召回重要信息，并讨论图结构扩展。这些系统共享检索思路，但不是简单将聊天切片后放进向量库就结束。[MemGPT](https://arxiv.org/abs/2310.08560)、[Generative Agents](https://arxiv.org/abs/2304.03442)、[Mem0](https://arxiv.org/abs/2504.19413)

可观察到的趋势是：从被动检索发展到主动管理工作集与记忆更新；从孤立文本片段发展到时间、实体和关系；从只比问答准确率发展到成本、延迟、冲突更新和长期任务评测。这是根据上述公开架构及评测方向作出的归纳，不是所有厂商都采用同一内部实现的断言。商业产品内部写入/排序细节未公开时，应明确未知。

最小面试实现优先选择可解释方案：完整日志作为事实源，recent turns + compact summary 保持对话，todo 保存显式任务状态。后续增加基于 SQLite FTS 的关键词召回，再以实测决定是否需要向量或图。记忆系统再复杂，也必须在“改了要求能记住、不能串窗口、不能记错已执行动作”上先过关。
